# V7 Phase 5 Compact Operator Identity UX

## Purpose

Identity UX must stay calm and workflow-oriented.

It must not become a giant customer database or noisy enterprise dashboard.

## Main Summary

The first identity view should show:

- organizations with affected user counts;
- pending confirmations;
- onboarding failures;
- active users/devices;
- reconnect issues;
- stale or revoked consistency risks.

## Grouped Views

Recommended groups:

- Organizations;
- Users;
- Devices;
- Onboarding;
- Profile Delivery;
- Policy;
- Audit.

## Drill-Down

Detailed views may show:

- raw DB fields;
- delivery token history;
- connect sessions;
- provisioning job details;
- registry/runtime mismatch evidence.

These should not be the first screen.

## Operator Questions

The UI should answer:

- Who cannot connect?
- Which organization is affected?
- Which devices need action?
- Which profiles are stale or revoked?
- What is the safe next step?
