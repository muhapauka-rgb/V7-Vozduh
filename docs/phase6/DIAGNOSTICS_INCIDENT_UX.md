# V7 Phase 6 Diagnostics And Incident UX

## Purpose

Diagnostics should explain incidents, not overwhelm the operator.

## Diagnostic Groups

- Routing;
- Channels;
- Services;
- Users;
- Trusted RU;
- Autoswitch;
- Provisioning;
- Security.

## Incident View

Incidents must show:

- what is broken;
- who is affected;
- severity;
- probable cause;
- suggested safe action;
- verification state.

## Current Foundation

Current admin has:

- checks page;
- events/logs page;
- service matrix;
- kill switch view;
- user readiness;
- trusted RU checks;
- autoswitch plan.

## Future Rule

Diagnostics pages should not become the overview. They are drill-down from incidents and workflow cards.
