# L3 Reality Audit

Дата: 2026-06-30 18:44:53

Статус: SOURCE_CODE_ONLY_AUDIT

Финальный вердикт: L3_PARTIALLY_IMPLEMENTED

## Summary

Проверка выполнялась по исходному коду как единственному источнику истины. Инженерные отчеты и статусы не использовались как доказательство реализации.

Результат: в `tools/v7-users-autoswitch` существует реальный исполняемый L3-путь, который при включенной `EMERGENCY_FAILOVER_AUTONOMY`, наличии одного безопасного failover-кандидата и успешных live-гейтах может дойти до `_run_switch`, затем выполнить verification и rollback при failure.

Но полноценная автономная L3 Runtime-петля пока не подтверждена:

- стандартный production systemd-путь запускает `v7-users-autoswitch --apply` без явного L3-флага;
- Admin guarded apply также запускает обычный guarded apply без L3-флага;
- wake не является отдельным event-driven runtime dispatcher, а вычисляется внутри planner run;
- incident lifecycle не является постоянным lifecycle owner, а формируется как plan/read-model context;
- большинство Production Behavior Contracts являются read-model/diagnostic, а не отдельными executable state transitions;
- L3 certification/validation ladder является read-model, не исполняющей лестницей;
- L3 learning closure после autonomous apply подтверждена только как audit/closure target, не как полный Feedback -> Learning -> Trust -> Promotion path.

## Реальный L3 Call Graph

Исполняемый L3-путь существует:

```text
main()
-> AutoswitchPlanner.plan()
-> _emergency_failover_authority_gate()
-> _l3_wake_decision()
-> _l3_incident_context()
-> apply()
-> _l3_execution_eligibility()
-> _run_switch()
-> _verify_routes()
-> _verify_emergency_required_services()
-> _run_switch(..., reason="rollback") on verification failure
-> _update_safety_after_apply()
-> finalize_operation()
-> _emit_terminal_audit()
```

Ключевые доказательства:

- L3 policy defaults exist but disabled by default: `tools/v7-users-autoswitch:137`.
- L3 can be enabled by policy/org policy or `--emergency-failover-autonomy`: `tools/v7-users-autoswitch:761`.
- Authority gate authorizes bounded one-user emergency failover: `tools/v7-users-autoswitch:845`.
- Wake is evaluated from explicit or inferred failure source: `tools/v7-users-autoswitch:1020`.
- Incident context/read model is created during planning: `tools/v7-users-autoswitch:1368`.
- Plan consumes L3 authority gate and marks selected moves as `emergency_failover`: `tools/v7-users-autoswitch:4856`.
- Final L3 eligibility gate runs before apply: `tools/v7-users-autoswitch:5559`.
- Apply calls `_run_switch`: `tools/v7-users-autoswitch:7154`.
- Verification failure can invoke rollback: `tools/v7-users-autoswitch:7181`.
- `_run_switch` executes `v7-user-switch`: `tools/v7-users-autoswitch:7466`.

## Runtime Integration Findings

`systemd/v7-users-autoswitch.service` runs:

```text
ExecStart=/usr/local/bin/v7-users-autoswitch --apply
```

It does not pass `--emergency-failover-autonomy`. L3 can still be enabled by `/etc/v7/policy.json` or org policy, but source code does not prove that production currently runs autonomous L3 by default.

`admin/v7-admin-api` guarded apply runs:

```text
v7-users-autoswitch --mode guarded --apply --pretty
```

It also does not pass `--emergency-failover-autonomy`.

`tools/v7-governed-canary-dry-run-cycle` uses governed canary apply and does not pass the L3 autonomy flag.

## Exact Gaps In Dependency Order

1. Event-driven wake integration is incomplete.
   - Existing code evaluates wake inside planner execution.
   - Missing proof: external confirmed service/current-channel failure event invokes L3 Runtime automatically.

2. Persistent incident lifecycle is incomplete.
   - Existing code creates incident context in the plan.
   - Missing proof: persisted incident state machine with durable merge/split/collapse/retry lifecycle.

3. Production runtime activation is incomplete.
   - Existing systemd service runs autoswitch apply, but not explicit L3 autonomy.
   - L3 depends on policy enablement or explicit CLI flag.

4. Behavior contracts are not all executable.
   - Target lost and unknown state are executable.
   - Merge/split/event collapse/late/duplicate/recovery behaviors are mostly read-model/diagnostic.

5. Full autonomous learning closure is incomplete.
   - Autoswitch emits terminal audit and closure target.
   - Full autonomous L3 path to Feedback -> Learning -> Trust -> Evidence -> Promotion was not proven from source.

6. Certification path is not executable.
   - Validation ladder and certification pipeline are exposed as read models.
   - They do not execute production certification steps.

## Final Answer To Core Question

Question:

Does a real autonomous L3 Emergency Autonomous Failover implementation now exist?

Answer:

Partially. A real executable L3 emergency failover path exists in source code and can move one user when L3 authority is enabled and all gates pass. However, the full autonomous production L3 control loop is not yet fully materialized as runtime-integrated, event-driven, incident-persistent, learning-closed and certification-ready production automation.

Final verdict:

L3_PARTIALLY_IMPLEMENTED
