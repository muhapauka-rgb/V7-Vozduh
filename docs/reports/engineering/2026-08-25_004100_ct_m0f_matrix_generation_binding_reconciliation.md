# CT-M0F: reconciliation of controlled transaction across a Matrix generation

Date: 2026-08-25  
Scope: existing `admin_core.operator_execution`, governed cycle and existing
autoswitch consumer. No new owner, state store, Matrix, Planner, timer or
authority was introduced.

## Purpose

Keep one certification-only identity on its governed source from controlled
setup through controlled failure and the exact Packet/Lease/Apply operation.
Normal recovery and rebalancing must not independently move that identity
while the existing reservation-backed transaction is active.

## First live controlled run: evidence and finding

Deployed baseline `9b090006f658fb55658ad7c6c8a5731fd7b580d1` was exercised
with only Polygon identity `10.7.0.92` on controlled source
`amneziawg-exec-20260528-10-8-1-14`; target selection was owner-backed `awg3`.

The controlled condition created durable transaction reservation
`ctm0ftx_edc1a69a84eefc7b29c4ad3f`, then an ordinary manually-started Matrix
generation completed successfully.  During the reservation interval the user
remained on its controlled source: no ordinary-user change and no independent
`autoswitch_failover` transfer occurred.  This proves the new existing
autoswitch-consumer guard held at the intended boundary.

The governed path stopped safely before Apply with
`ct_m0f_transaction_reservation_not_exact_at_packet_lease_bind`.  The lease
and sample reservation were created, but the pre-T0 derived Matrix selection
fingerprint did not equal the value regenerated by the fresh Matrix cycle.
The transaction then emitted its terminal record and released itself.  The
source remained the user assignment; no user or production route was moved.

This was not a failure of health, Matrix, reservation expiry or normal
recovery.  It was an overly strict comparison of a derived receipt that is
expected to change across a fresh Matrix generation.

## Correction

The exact handoff is now defined by durable, invariant fields:

```text
certification-only user + source + target
+ controlled-source reservation id
+ exact source registry-line fingerprint
+ exact Packet + Lease + governed operation id
```

The pre-T0 Matrix selection fingerprint remains preserved on the transaction
reservation.  The fresh Matrix-to-Planner fingerprint is now recorded on the
Packet/Lease binding as independent generation evidence, rather than being
mistakenly required to be equal to the pre-T0 value.  Thus a genuine source
or reservation change still stops safely, while the required ordinary Matrix
generation can legitimately refresh its derived selection receipt.

## Safety and effect

The change still does not pin a user and does not disable health.  It only
lets the already-owned controlled reservation be consumed correctly by the
existing governed path.  Other identities remain subject to normal recovery;
this identity is released on governed completion, expiry, STOP_SAFE or
explicit rollback/recovery cleanup.
