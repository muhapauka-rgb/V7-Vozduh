## Pipefail Probe

Source check in `v7-reconcile-check`:

```bash
set -euo pipefail
if ! ip -4 rule show 2>/dev/null | grep -q "from $ip lookup $table"; then
  err "user=$ip missing ip rule lookup table $table"
fi
```

Read-only probe showed that the same existing rule can return non-zero under
`pipefail` while returning `0` without `pipefail`:

```text
PATTERN=from 10.0.0.3 lookup 101
pipefail_rc_1=141
no_pipefail_rc_1=0
pipefail_rc_2=0
no_pipefail_rc_2=0
pipefail_rc_3=141
no_pipefail_rc_3=0
pipefail_rc_4=141
no_pipefail_rc_4=0
pipefail_rc_5=141
no_pipefail_rc_5=0

PATTERN=from 10.7.0.13 lookup 1011
pipefail_rc_1=141
no_pipefail_rc_1=0
pipefail_rc_2=0
no_pipefail_rc_2=0
pipefail_rc_3=141
no_pipefail_rc_3=0

PATTERN=from 10.7.0.15 lookup 1013
pipefail_rc_4=141
no_pipefail_rc_4=0
```

`141` is consistent with SIGPIPE from the upstream `ip` command after `grep -q`
exits early on a match. With `pipefail`, the pipeline is treated as failed even
though `grep` found the rule.
