# E14 Read-Only Operator API Model

## Purpose

The future operator UI needs a read-only control-plane foundation. E14 defines
the shape of that foundation without implementing an API server, database
migration, frontend, or runtime mutation.

## Architecture

```text
runtime tools / evidence / state files
  -> read-only collectors
  -> canonical governance objects
  -> freshness and lineage normalizer
  -> read-only operator API
  -> UI progressive disclosure
```

Collectors must be read-only. They may run diagnostics and parse evidence, but
they must not call mutating tools, deploy, restart services, move users, apply
routes, or clear barriers.

## Endpoint Groups

### Overview

```text
GET /operator/overview
GET /operator/overview/freshness
GET /operator/governance-verdict
```

Returns:

- RuntimeSnapshot summary;
- GovernanceVerdict;
- current blockers;
- safe next action;
- execution allowed now.

### Movement Preview

```text
GET /operator/movement/previews
GET /operator/movement/previews/{preview_id}
GET /operator/movement/previews/{preview_id}/fingerprint
```

Returns:

- SelectedMoveSet;
- MovementApproval draft shape;
- BlastRadiusContract;
- rollback readiness summary.

Read-only constraint:

- endpoint may show preview material generated by approved read-only planning;
- it must not execute movement or autoswitch apply.

### Operation History

```text
GET /operator/operations
GET /operator/operations/{operation_id}
GET /operator/operations/{operation_id}/replay
```

Returns:

- OperationTimeline;
- MovementLineage;
- RestoreLineage;
- final report links.

### Timeline

```text
GET /operator/timelines/{operation_id}
GET /operator/timelines/{operation_id}/events/{event_id}
```

Returns:

- compact event list by default;
- raw evidence refs only when event is expanded.

### Target Pool

```text
GET /operator/targets
GET /operator/targets/{target_id}
GET /operator/targets/{target_id}/readiness
GET /operator/targets/{target_id}/pressure
```

Returns:

- TargetReadiness;
- TargetPressureState;
- reservation state;
- capacity summary.

### Restore State

```text
GET /operator/restore
GET /operator/restore/{restore_id}
GET /operator/restore/{restore_id}/settle
GET /operator/restore/{restore_id}/barrier
```

Returns:

- RestoreLineage;
- RestoreSettleState;
- barrier summary;
- delayed monitoring requirement.

### Evidence

```text
GET /operator/evidence
GET /operator/evidence/{evidence_id}
GET /operator/evidence/{evidence_id}/raw
```

Returns:

- evidence metadata first;
- raw content only through explicit drill-down.

### Generation Governance

```text
GET /operator/generation
GET /operator/generation/{token_id}
GET /operator/generation/{token_id}/replay-protection
```

Returns:

- GenerationLineage;
- GenerationClearance;
- ReplayProtection.

### Delayed Movement

```text
GET /operator/delayed-movement
GET /operator/delayed-movement/{monitor_id}
GET /operator/delayed-movement/{monitor_id}/samples
```

Returns:

- DelayedMovementState;
- sample summaries;
- movement observed yes/no.

### Runtime Truth Freshness

```text
GET /operator/freshness
GET /operator/freshness/conflicts
GET /operator/freshness/stale-objects
```

Returns:

- freshness scores;
- stale reasons;
- conflicting evidence;
- invalidated approvals.

## Caching Semantics

- Overview payloads are short-lived and must display `collected_at`.
- Approval-related payloads are not silently reused after expiry.
- Evidence metadata may be cached longer than live runtime state.
- Raw evidence is immutable once archived.
- Live runtime snapshots must include state hashes so UI can detect drift.

## Freshness Semantics

Every response includes:

- collected_at;
- valid_until;
- state_source;
- stale boolean;
- stale reasons;
- source refs;
- confidence.

If stale is true, any approval CTA using that object is disabled.

## Mobile Payloads

Mobile endpoints or response modes should include:

- headline status;
- blockers;
- affected users count;
- target delta summary;
- rollback status;
- safe next action;
- evidence freshness.

Deep evidence and raw JSON stay behind separate endpoints.

## Progressive Disclosure

Default response:

- summary;
- status;
- blocker;
- ids linking to detail objects.

Expanded response:

- lineages;
- evidence refs;
- raw excerpts;
- schema payloads.

## Forbidden API Surface

The read-only foundation must not expose:

- POST movement execution;
- POST autoswitch apply;
- POST route sync;
- POST kill switch mutation;
- POST Direct/RU mutation;
- POST Trusted RU refresh;
- generic shell command endpoints;
- one-click emergency repair.

## Stage 2 Finalization Extension

Implemented read-only productization endpoint:

```text
GET /api/operator/audit-export-preview?id=<operation_id>
```

Returns an export-ready audit/runbook packet preview with:

- operation summary;
- runtime verdict;
- approval preview summary;
- blast radius;
- generation guard;
- rollback manifest;
- delayed movement summary;
- evidence references;
- mutation statement;
- stale/conflict warnings;
- multi-operator audit model placeholder.

The endpoint is GET-only, preview-only, redacted, and does not write export files.

## API Verdict

The API model is safe for an operator UI foundation because it normalizes truth
and evidence without introducing mutation paths.
