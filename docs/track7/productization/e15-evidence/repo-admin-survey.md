# E15 Repo/Admin Survey

## Purpose

E15 implements the first read-only operator observability UI foundation. This
survey records the integration path before coding and confirms the block did
not require runtime mutation or unsafe admin changes.

## Current Admin Structure

| Area | Finding | E15 decision |
|---|---|---|
| Admin runtime | `admin/v7-admin-api` is the embedded admin monolith and serves `/admin-v2`. | Touch only narrowly: import read-only adapter, add GET endpoints, add Operator tab/section. |
| Extracted helpers | `admin_core/events.py`, `registry_readers.py`, `sanitize.py`, `time.py` exist as small helper modules. | Add `admin_core/operator_observability.py` as read-only file/evidence adapter. |
| Frontend scaffolding | `web/src/*` contains README/scaffold docs, not an active bundled React app. | Do not build React yet; integrate into existing embedded admin UI. |
| Design system | Admin already uses dark tokens: `--bg`, `--panel`, `--line`, `--text`, `--muted`, `--green`, `--blue`, `--yellow`, `--red`. | Reuse same tokens and existing `panel`, `pill`, `toolbar`, `module-page` patterns. |
| Navigation | `/admin-v2` uses top nav with tab sections and hash routing. | Add `operator` tab without changing existing tabs. |
| Existing API pattern | Authenticated GET endpoints are handled in `do_GET`; mutating actions are under `/api/actions/*` in `do_POST`. | Add only authenticated GET endpoints under `/api/operator/*`; no POST. |
| Endpoint inventory | Static inventory generated by `tools/v7-admin-endpoint-inventory`. | Regenerate inventory and update contract counts. |
| Tests | Python unittest contract/unit tests exist. | Add adapter/unit tests and extend endpoint inventory contract. |

## Files Intentionally Not Touched

- runtime state under `/opt/v7`;
- routing policy files;
- users registry;
- egress registry;
- autoswitch runtime files;
- kill switch configuration;
- Direct/RU and Trusted RU runtime state;
- systemd units;
- existing mutating admin actions.

## Safe Implementation Path

1. Add read-only adapter that reads files and evidence only.
2. Add authenticated GET endpoints:
   - `/api/operator/overview`
   - `/api/operator/targets`
   - `/api/operator/operations`
   - `/api/operator/evidence`
   - `/api/operator/delayed-movement`
3. Add `Operator` tab to `/admin-v2`.
4. Render five read-only surfaces:
   - Runtime Overview;
   - Target Pool;
   - Operations History;
   - Evidence Viewer;
   - Delayed Movement Monitor.
5. Add tests for missing data, conservative aggregation, target parsing, secret
   redaction, and no POST operator namespace.

## Abort Criteria Review

- Admin structure identified: yes.
- Safe implementation path identified: yes.
- Build/test commands inferred: yes, Python unittest and py_compile.
- Runtime mutation required: no.
- Existing admin module risk: bounded and acceptable.

## Integration Verdict

Implementation can proceed safely as a read-only embedded admin extension.
